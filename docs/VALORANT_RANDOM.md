# VALORANT ランダムピック / 実戦向け構成

対象: /valorant random [map]、Issue #589、PR #590。2026-10-30 Patch 13.09。

## 新方式（旧VC自動抽選は廃止）

/valorant random はDiscordに参加募集メッセージを投稿します。VC接続は不要。
参加、参加取消、抽選、募集取消ボタンを表示し、押した本人のみ参加/取消できます。
募集はGuild/Channel/UUIDで識別され、作成者または ManageGuild/Administrator 権限保持者のみ抽選と取消が可能。
作成者は自動参加しません。参加者0名の抽選は拒否します。上限5名（Guild設定で1～5）。
募集期限は5～180分（既定30分）で、Workerが期限切れを毎時EXPIREDへ更新します。ボタン操作時にも期限切れを判定します。
Bot再起動後もDB正本を使用し、同一セッションの並行操作は行ロックとReadCommitted transactionで直列化します。
Discord表示更新が失敗してもDBの状態は保持します。古いメッセージ表示は後続の操作時に更新されます。
現在の実装は定期的な期限切れメッセージ同期を持ちません。時間経過時点の自動ボタン無効化は未完了です。

mapを省略すると、Guildの有効候補からcrypto.randomInt/Fisher–Yatesによる公平な完全ランダム抽選を行います。
ランク・ロール・マップ・履歴・勝率を参照しません。エージェント重複はありません。

mapを指定すると、有効な複数の構成テンプレートからランダムに選択します。
テンプレートにはエントリー、スモーク、索敵、防衛、相互補完の順で役割を並べています。
1～4人では先頭から割り当て、5人編成として未完成であることを表示します。
有効候補不足でテンプレートが成立しない場合は失敗として参加状態を維持します。
テンプレートは公式マップ一覧/13.09を参照した開発者提案であり、勝率やプロ実績を根拠とした最適構成ではありません。
2026-10-13 Patch 13.08でアセント/スプリットがランクローテーションから除外されていても、カスタム用の候補として選択可能です。

## 再抽選 / @メンバー直接指定（2026-10-31）

- 募集方式は従来どおり `/valorant random [map]`。参加者が参加ボタンで確定抽選したあと、同じDiscordメッセージから**再抽選**を実行できます。
- `/valorant random member1:@A [member2:@B ... member5:@E] [map:マップ]` は@指定されたメンバーだけを**その場で抽選**し、参加・参加取消・抽選・募集取消ボタンを表示しません。抽選結果には**再抽選**ボタンのみ表示します。作成者は明示的に指定しない限り抽選に含まれません。
- member1～member5 はすべて任意、1人以上指定すると即時抽選、未指定なら参加募集です。順序は自由ですが、サーバー外のユーザー・Bot・重複指定は拒否します。Guild最大人数設定（1～5）を超える場合も拒否し、DBに不完全なセッションを残しません。
- 再抽選は**作成者またはManageGuild/Administrator権限者のみ**、セッション期限内に可能です。期限は募集と同じGuild設定（5～180分、既定30分）、再抽選時に更新します。現在の参加メンバー・マップ・抽選モードをそのまま引き継ぎ、有効なGuildのAgent候補で引き直します。新旧の割当が偶然一致する場合があります。
- **履歴不変性**: 再抽選では元の完了済みDB行を上書きせず、新しいCOMPLETED行を追加し、Discord messageIdを原子的に引き継ぎます。従来の結果と既存の試合結果は保持され、Studioの抽選統計ではそれぞれ個別の抽選として記録されます。
- 期限・Guild IAM・メッセージID・旧ボタンの再利用をDB行ロック付きトランザクションで検査し、同時クリックによる二重再抽選を防止します。BotがDiscordメッセージを編集できなかった場合もDB正本は保たれます。

## DB・互換性・プライバシー

新規 migration 20261030100000_valorant_pick_sessions でセッション・参加者テーブルを追加。
同一行のguildIdを必ず指定して参照します。参加者(userId)は該当募集にのみ保存します。
COMPLETED時に候補スナップショット、実際の割当、ルールバージョンと完了日時を原子的に保存します。
新テーブルは既存のValorantAccountLink/ValorantRoster/ValorantAgentを変更しません。
参加者のDiscord IDは終了済みセッション作成後90日間保持します。
Workerが1時間間隔で終了済みセッションの識別子を匿名化します（起動時にも実行）。
セッション・抽選候補・エージェント構成・集計値は削除せず残し、
参加者行を削除し、抽選/試合結果JSONのuserId、作成者/登録者ID、matchIdを削除・匿名化します。
100件ずつではなく50件ずつ処理し、失敗時は次のWorker実行で再試行します。
匿名化済み結果はプレイヤー別の長期追跡には利用できません。

## 統計・試合結果（本番適用済み）

Studio統計ダッシュボード・Guild別履歴集計・参加者傾向・手動試合結果登録は本番へ反映済みです。認証済み画面操作による受入は未検証です。
選出率は候補入りした抽選セッション数を分母にする定義で、現在はマップ・モードを横断したエージェント別の集計値として算出します。
自動試合結果取得は公式VAL-MATCH-V1とRiot承認Production Key/RSOの取得後に実装。
既存Riot ID手入力は試合履歴取得に対するオプトインではありません。
HenrikDevでは事前同意と利用規約/用途制限の確認が必要なため、現段階で自動収集しません。
Match IDだけをもって本人の結果と見なしたり、抽選時刻のみで確定したりしません。

## マップ別戦術候補の改善（Patch 13.09 / v2）

参照した比較の考え方: [THESPIKE.GG「エージェント構成のスタッツ」](https://www.thespike.gg/jp/valorant-stats/agents-compositions)。
このページはマップごとの「プレイ済み」「ピック率」「勝利」「勝率」などを比較する入口です。
ただし、**2026-10-30時点で個別の構成データ行は公開ページから検証できず、採用数・勝率はHertaに取り込んでいません。**
同サイトの規約は無断複製・自動クロールを制限しています。API/HTMLをスクレイピングして定期取り込みする設計ではありません。

- Herta独自の編集上の戦術候補を各マップ**3構成**に拡充。個別構成の採用率・勝率を推測しません。
- 5人では構成単位で抽選し、メンバーだけをバラバラに組み替えて役割やシナジーを破壊しないようにしています。
- 1～4人では役割順の先頭から割り当て、未完成であることを明示。重複した部分構成は候補から除外します。
- マップ・人数・Guildの有効候補に適合する構成のみが対象。条件を満たすものがなければfail-closed。
- **検証済みかつ利用許諾済み**の構成統計（同一パッチ・60日以内・30試合以上・対象構成の全件が揃い、同じマップ総試合数を使用）を任意に渡せるスコア関数を追加。実データが未投入の現状は**候補構成を等確率**で抽選。
- 将来統計データを投入する場合も、勝率は20+α相当の縮約（Beta prior）とマップ別採用比率を組み合わせた選択重みにのみ利用し、実際の試合勝率を予測する値とは表示しません。
- **マップ未指定時のFisher–Yates完全ランダムには手を加えていません。**

検証の正本: [Riot公式パッチ13.08](https://playvalorant.com/ja-jp/news/game-updates/valorant-patch-notes-13-08/)（マップ変更）／[13.09](https://playvalorant.com/ja-jp/news/game-updates/valorant-patch-notes-1309/)（現行パッチ）。

### 統計データを更新する際の運用ルール

1. 対象のマップ、対象パッチ、日付、地域・イベント、試合数、勝利数、対象マップの全試合数、構成5人が揃った記録を確保。
2. ソースのデータ利用許諾・出典を確認。未承認のスクレイピングは禁止。
3. 30試合未満・60日超・パッチ不一致・一部だけのサンプルは採用せず、均等抽選にフォールバック。
4. 規約やマップ仕様更新時は新versionとして変更し、単体テストと本番検証を行う。
