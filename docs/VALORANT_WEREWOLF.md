# VALORANT 人狼モード（トロールガチャ S4）

対象: `/valorant werewolf`、Issue #1049。トロールガチャ Epic（ivrm-web #2010）の S4。
縛り抽選は S1 の Bot API（ivrm-web `POST /valorant/bot/troll/draw`）を使う。

本書は開発仕様であり、マージ・本番反映・有人実機確認を成功扱いしない。
本番の migration 適用・フラグ有効化は個別承認 Gate に従う。

## 遊び方

1. `/valorant werewolf [vc_auto_join:true]` で部屋を作る（募集は通常のピック募集と同じ
   セッション基盤。参加ボタン / VC一括追加 / 参加者管理 / VC自動参加がそのまま使える）。
2. 3〜5人集まったら作成者または管理者が「🐺 開始」を押す。
   - 人狼が暗号論的乱数で1人選ばれ、その1人だけに秘密の縛りが抽選される。
   - 開始した時点で参加者（roster）は固定され、参加・退出・管理・VC自動参加は止まる。
3. 人狼本人は「🎭 自分の縛りを確認」ボタン（ephemeral）でだけ自分の縛りを見られる。
   市民には縛りは配られない。縛りを伏せて試合する。
4. 試合後、作成者または管理者が「🗳 投票へ進む」を押し、参加者は「投票する」ボタンから
   ephemeral のセレクトで1人へ投票する（自分には投票できない。締切まで変更可）。
5. 全員投票で自動締切。手動締切も可（未投票者は棄権扱い）。投票が0件なら勝敗なしで
   部屋は中止になり、秘密は公開されない。
6. 最多票が1人ならその人が「指名」される。同票なら同票者だけで決選投票（最大1回）。
   決選でも同票なら指名なし。
7. 結果発表で初めて、人狼・秘密の縛り・指名者・勝敗・ラウンド別票数・罰ゲームが
   公開される。誰が誰へ投票したか（個別の投票先）は最後まで公開しない。

## 勝敗と罰ゲーム

- 指名者が人狼なら市民の勝ち、外したら（または指名なしなら）人狼の勝ち。
- 罰ゲームは本投票（第1ラウンド）の最少票者（0票含む、同票はランダム、人狼も対象）に
  1件抽選される。カテゴリは `punishment` のみ、レアリティフィルターは `all` 固定。

## ルール詳細（確定仕様）

- 開始は3〜5人。部屋作成は1人から可。初版はエージェント割当なし。
- 秘密の縛りのカテゴリは `troll` / `settings` / `custom` のみ（`punishment` は混ぜない）。
- 縛りオフ（troll-off）は人狼選定に適用しない（人狼部屋に縛りオフボタンは無い）。
- 投票・決選の目安は5分。scheduler は入れず、期限超過は次のボタン操作時に
  遅延締切する（手動締切と同じ扱い）。
- 試合中にサーバーを抜けた人も roster に残り、投票では棄権として扱う。
- 複数の部屋へ同時に参加できる（既存の募集原則どおり）。

## 秘匿の境界（実装上の不変条件）

- 秘密（人狼の Discord ID・秘密の縛り）は専用テーブル
  `valorant_werewolf_secrets` にだけ保存し、公開側のセッション `result` JSON や
  ゲーム行には結果確定まで入れない。公開 Embed / DTO は秘密テーブルを参照しない。
- 秘密の表示経路は ephemeral の「自分の縛りを確認」だけ。DM は使わない。
  ログにも人狼 ID・縛り文は出さない（guildId / sessionId / エラーコードのみ）。
- 秘密の抽選は fail-closed: Bot API の抽選が失敗したら開始を確定せず、
  部屋は「開始処理中（ASSIGNING）」のまま再試行できる。再試行しても人狼は
  引き直されない（冪等キー `herta-valorant-werewolf:<sessionId>:secret:v1`）。
  罰ゲームは `:punishment:v1`。罰ゲームの抽選失敗は結果を確定させたうえで
  「引き直し」ボタンから再試行できる（fail-soft）。
- 中止した部屋の秘密は公開されない。

## 有効化

- Guild 設定 `trollWerewolfEnabled`（既定 OFF、プラグインカタログの
  「トロールガチャ」セクション）と、S2 と同じ Bot API 環境
  （`IVRM_WEB_API_BASE_URL` / `HERTA_TROLL_BOT_SECRET`）の両方が必要。
- Studio の通常の抽選結果・統計からは人狼セッションを除外している
  （`mode = 'WEREWOLF'` は結果一覧・手動の試合結果登録・統計の対象外）。
- Web（メンバーポータル）向けにはドメインサービスと DTO
  （`valorant-werewolf-api.ts` の公開 view / 本人 view）までを用意し、
  HTTP / BFF は S6（ivrm-web #2013 / Herta #1050）の範囲とする。

## データと保持

- テーブル: `valorant_werewolf_games`（進行と公開結果）、
  `valorant_werewolf_secrets`（秘密、結果確定後は公開スナップショットへ複写済み）、
  `valorant_werewolf_votes`（PK (sessionId, round, voterUserId) で二重投票を防止）。
- 状態遷移は pick セッション行の行ロック + ReadCommitted transaction で直列化する。
- 保持は既存 VALORANT と同じ90日匿名化（`valorant-retention.ts`）:
  終端から90日で投票行と秘密行を削除し、ゲームの roster / 票数スナップショットは
  件数だけに落とす。個別の投票先は匿名化後も残らない。
